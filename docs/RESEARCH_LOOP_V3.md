# 研究循环 v3：大模型在全量本地数据上提出因子（2026-10-18）

## 为什么做 v3

v2（`docs/RESEARCH_LOOP_V2.md`）只问一个问题：约 107 个山寨币里，哪些会在 30 天内翻倍。它用的是一年数据、5 个字段。
到 10/18 跑了 89 轮、156 个公式，没有一个通过闸门，最近几轮基本在换说法重复老想法（"隐含流通量增长""资金费符号持续"每轮都撞重复）。

10/15 起，本地有了全量数据（`docs/LOCAL_DATA_INVENTORY.md`）：654 个币安 USDT 永续（含已下架）自 2020 年的日线、资金费率、溢价，以及 Coinglass 每币 13 类日线。
v3 让大模型在这份数据上回答前向跟踪器真正交易的问题：
**按公式给当天流动性最好的约 150 个永续排序，能不能预测未来 7 天的收益？扣掉已知因子之后还有没有新信息？扣掉成本和资金费之后还赚不赚？**

同一天用户决定暂停自治交易代理（它 10/14 起 3,000 多次决策全是观望），把模型预算转到研究上。

## 流程

```
大模型（只看到匿名的面板概况 + 自己公式的开发期结果）
  → JSON 公式（封闭 DSL，不执行代码；可用 21 个字段）
  → 开发期 / 留出期评估（留出期结果和闸门结论对模型隐藏）
  → 闸门（增量信息的门槛随试验台账增长）
  → 冻结 → 只用冻结后新增的数据终审 → 人工决定是否建纸面跟踪器
```

研究专用：不注册策略、不下单、不改配置。计算在独立进程里跑，网页进程只负责定时启动和读状态。

| 文件 | 作用 |
|---|---|
| `core/research/xs_daily_panel.py` | 研究面板：从本地文件拼出每天 × 每个币的宽表、逐日币池、7 天标签、已知因子；缓存在 `data/research/xs_daily_panel/`，超过 20 小时自动重建（约 1 分钟） |
| `core/research/xs_feature_dsl.py` | 和 v2 共用的公式 DSL；v3 传入自己的字段表，并用向量化版本一次算完所有币（与逐币计算逐值一致，有测试） |
| `core/research/xs_return_evaluation.py` | 评分：IC、打乱零分布、正交化增量、扣成本组合 |
| `core/ai/research_loop_v3.py` | 循环：配置、提示词、台账、闸门、冻结、前向终审、启动独立进程 |
| `scripts/research_loop_v3.py` | 命令行：`--round` 跑一轮（调度器用）、`--build-panel`、`--calibrate`、`--status` |
| API | `GET/PATCH /api/ai/research-loop-v3`，`POST /api/ai/research-loop-v3/run`；AI 研究页有"研究循环 v3"卡片 |
| 状态 | `data/research/ai/research_loop_v3.json`（台账），运行锁 `research_loop_v3.lock`，日志 `logs/research_loop_v3.log` |

## 预登记的协议（第一轮之前写死）

**币池（逐日、不看未来）：** 654 个永续里，当天有收盘价和成交、本地已有 ≥ 60 天历史、
没有锚定（90 天最高收盘 / 最低收盘 > 1.10），并排除稳定币、黄金代币和 BTCDOM；
满足条件的按 30 天平均成交额取前 150 个。2020 年永续少，币池中位只有 23 个，每天不足 30 个币不计分。

**时点：** 第 D 天的值都是 D+1 日 00:00 UTC 时已知的。
多空比是在时间戳那一刻拍的快照，所以戳在 D+1 00:00 的那张算第 D 天（和跟踪器一致）。
净持仓变化保留原时间戳：如果它其实也是快照，只会晚一天，不会早一天。

**标签：** 从第 D 天收盘到第 D+7 天收盘的收益。7 天内下架的永续按最后一根收盘价出场，即真实持仓能拿到的价格，所以濒死的币不会被悄悄剔掉。

**可用字段（21 个）：**
- 币安：收盘、开、高、低、成交额、资金费率（当天结算之和）、溢价指数。
- Coinglass：跨所 OI 加权资金费率、跨所持仓量、多头 / 空头爆仓额、合约主动买 / 卖额、10 家现货的主动买 / 卖额。
- 币安多空比：全部账户、大户账户、大户持仓。
- 币安净多头 / 净空头变化（美元）。
- BTC 收盘价。

**已知因子（新公式要在它们之外提供信息）：**
- 21 日 EMA 偏离（短期反转）、30 天动量、30 天波动率、30 天平均成交额（取对数）、7 天平均资金费率、7 天持仓量变化；
- 前向跟踪器在跑的 8 信号 Coinglass 合成（等权、训练期 IC 符号）。

**指标：**

| 指标 | 含义 | 防的是什么 |
|---|---|---|
| ic | 每天公式排名与未来 7 天收益排名的相关系数，取平均 | — |
| z | 相对**按币整体打乱**的零分布（每个币换成另一个币的整段公式值，200 次）。借来的币某天没有数据时（上市晚、下架早），当天另找一个有数据的币顶上，不会用自己的数据；所以每次打乱排的币数和实际当天一样 | 币级持续性造成的假显著（v2 校准教训 1）；币数对不上造成的零分布过宽 |
| resid_ic / resid_z | 每天把公式排名对 7 个已知因子的排名做正交化后再算 IC，z 同样相对打乱零分布 | 换个说法重新发现已知因子（v2 教训 3、4）；已知因子的拷贝在这里恰好为 0 |
| nearest_factor | 和公式排名最相关的已知因子及相关系数 | 让模型知道自己撞了哪个已知因子 |
| net_per_book | 做多前五分之一、做空后五分之一，持有 7 天；每天建一份，7 个相位平均；按换掉的名字收 0.12% 往返成本，资金费按实际结算（多头付、空头收）；算术收益 | 秩 IC 为正但组合不赚：空头一侧的暴涨币会把组合拖垮 |
| net_per_book_ex_top3 | 去掉对组合贡献最大的 3 个币后重算 | 结论被一两个妖币撑起 |

**期间：** 开发期 2020-07-01 ~ 2023-12-31，结果反馈给模型。留出期 2024-01-01 ~ 最近一个有完整标签的日子，结果对模型隐藏。

**闸门（全部满足才冻结）：**
- 两期覆盖率 ≥ 50%；
- 开发期 z ≥ 1.645；
- 留出期 z ≥ 1.645；
- **留出期 resid_z ≥ Bonferroni(台账大小)**；
- 留出期 net_per_book > 0；
- 留出期 net_per_book_ex_top3 > 0。

**前向终审：** 冻结后积累 ≥ 182 天新数据，要求 z ≥ 1.645 且 net_per_book > 0，才算"前向确认"。
之后是否建纸面跟踪器由人决定。本地数据由定时任务补：币安每天，Coinglass 每周六。

**预算：** 每 6 小时一轮，每天最多 4 轮，每轮 3 个公式，打乱 200 次。每个公式约 3 分钟，一轮约 10 分钟。

## 校准（10/18 实测，真实面板，打乱 100 次）

`python scripts/research_loop_v3.py --calibrate`，结果在 `data/research/ai/research_loop_v3_calibration.json`（不进台账）：

| 检查 | 结果 | 期望 |
|---|---|---|
| 45 个随机持续序列（AR(1)、随机游走、币级固定特质各 15 个），开发期 z | 均值 0.01，标准差 0.97；超过 1.645 的 0 个 | 约 N(0,1)，约 5% 超过 |
| 同上，开发期增量 z | 均值 0.08，标准差 0.91；3 个（7%） | 同上 |
| 同上，留出期 z | 均值 −0.26，标准差 1.04；1 个（2%，z 3.0） | 同上 |
| 同上，留出期增量 z | 均值 −0.16，标准差 1.04；2 个（4%，最大 3.2，和上面是同一个 AR(1)） | 同上 |
| 随机序列走完整闸门（按只有 1 次试验的门槛 1.645） | 0 个通过；留出期组合净收益均值 −0.07%/期，47% 为正 | 不超过 5% |
| 植入信号：未来收益加强噪声，IC 约 0.03–0.04 | 开发期 z 10.0、增量 z 9.1；留出期 z 14.7、增量 z 13.3；组合净收益为正 | 远超门槛 |
| 植入信号：IC 约 0.10–0.13 | z 33–52 | 远超门槛 |
| 已知因子的拷贝（反转、波动率、Coinglass 合成） | 增量 IC 绝对值 ≤ 0.0009，增量 z 在 −0.28 到 +0.11 之间 | 约 0 |
| 对照：修正零分布之前（整列打乱，8 个随机序列） | 开发期 z 标准差约 0.3 | — |

45 个随机序列里最大的留出期 z 是 3.0。在 45 次独立抽样中出现一个 ≥ 3 的值，概率约 6%，属于正常范围。
台账一旦超过 20 个，闸门就到 2.81 以上；到 100 个是 3.29。

**检测力：** 留出期增量 IC 的零分布标准差约 0.0026，开发期约 0.0028。所以门槛大致对应：
- 台账 20 个：增量 IC 约 0.007；
- 台账 100 个：约 0.0084；
- 台账 500 个：约 0.0095。

作为参照，前向跟踪器在跑的 8 信号合成，留出期 IC 是 +0.017。

## 第一次检查时看到的现象

- **反转因子的 IC 为正，但组合不赚。** 21 日 EMA 偏离在开发期 IC +0.060（z 3.1），扣成本和资金费后的多空组合却每期 −0.55%。
  按对数收益算，多空差 +0.56%；按中位数算 +1.5%；按算术收益只剩 +0.24%，再扣成本就亏了。原因是空头那一档里不断有暴涨的币。
  所以闸门除了 IC，还要求组合净收益为正。
- **增量检验的数值陷阱。** 一个公式如果完全落在已知因子张成的空间里，正交化后剩下的只是 1e-16 量级的舍入误差。
  拿这点误差去算相关系数，结果是随机数。现在残差小于原排名范数的百万分之一时，增量 IC 直接记 0。
- **整列打乱在开发期太保守。** 最初的零分布像 v2 一样把整列随机换给另一个币。2020–2021 年永续很少，借来的币大多还没上市，
  开发期只剩 23% 的有效格子（每天平均 24 个币，实际是 106 个），三分之二的日子凑不够 30 个币。零分布因此被撑宽：
  8 个随机特征的开发期 z 标准差只有约 0.3（应接近 1），开发期闸门比名义上严得多，模型看到的开发期 z 也被低估。
  留出期保留 65%，同样偏保守。改成"缺数据就另找一个当天有数据的币顶上"后，有效格子回到 99.8% 以上，
  每个币在数据齐全的日子里仍然只带一个借来的轨迹（有测试）。下面的校准是改完之后跑的。

## 已知局限

- 留出期（2024 年起）在 10/11–10/12 的 Coinglass 研究里被人看过，但看的是那 8 个信号。
  模型新提的公式没被看过；不过人对这段行情的印象可能间接影响提示词和字段选择。最终裁决靠前向终审。
- 模型的训练数据覆盖这段历史。匿名化只能挡住"按币名回忆"，挡不住公式选择上的间接泄漏，同样靠前向终审兜底。
- Coinglass 字段每周六才更新，最近几天为空；前向终审按周推进，不影响结论，只是慢。
- 本环境的 BLAS 会原生崩溃（0xc06d007f）。评估只用逐元素运算和 pandas 排名，不用矩阵乘法、`lstsq`、`corrcoef`。
