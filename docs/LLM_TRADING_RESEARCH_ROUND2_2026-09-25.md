# 大模型交易：第二轮研究（2026-09-25）

第一轮（`docs/LLM_FORECASTING_RESEARCH_2026-09-25.md`）证明：自治代理的买卖判断和新闻情绪都没有可交易优势。
这一轮换思路：**不再问"怎么调代理"，而是找大模型可能有信息优势的地方，逐个测量。**
五个方向测了四个，全部证伪；第五个（Alpha 上币预测）数据不够，已开始前向采集。

---

## 1. 速度能不能救新闻信号？——不能

`scripts/news_llm_latency_curve.py`，BTC/ETH 1 分钟 K 线，3329 个去重事件。

- LLM 读方向**是对的**：宏观新闻发布后 +1 分钟按情绪方向走 +1.1bp（CI 在零上方）。
- 但整个移动只有 **~1bp**，吃单手续费一侧就 4~10bp。事件后 5 分钟波动中位 6.3bp，随机时刻 5.6bp——新闻几乎不动 BTC。
- 从 LLM 标注完成到 +60 分钟：−0.1bp。

**结论**：即使延迟为零也赚不到钱。主流币的新闻交易无论多快都是死路。

## 2. 大模型能不能预测波动率？——不能

`scripts/news_llm_vol_forecast.py`，下一小时对数已实现波动率，时间切分样本外：

| 模型 | 样本外 R² |
|---|---|
| HAR 基线（1h/24h/168h 波动 + 时段季节性） | 0.681 |
| + LLM 新闻特征（事件数、最大影响、宏观高影响数） | 0.678（增量 CI 在零下方） |

标准波动率模型已经包含了新闻能提供的一切。

## 3. AI 研究循环的审计：结构上找不到任何东西

大模型在系统里的另一种用法是**写策略**（研究循环，proposal → backtest → gate）。82 个提案里 80 个被拒、2 个"验证通过"。

| 问题 | 证据 |
|---|---|
| 回测窗口太短 | 配置 `days: 30`，83/85 个实验用 30 天 1h |
| 样本几乎为零 | 每个候选中位 **4 笔**交易，88% ≤10 笔 |
| 最优选择=选噪声 | 两个"通过"的：Sharpe 12.4（6 笔）、7.8（5 笔）；BTC 那个前向观察 0/3 |
| 搜索空间最难 | 100% BTC/ETH 1h，全市场效率最高的两个品种 |

门禁设计本身是好的（"等待足够的完整交易样本"，没有放行）；问题是**循环在一个不可能成功的设定里空转**。

## 4. 把大模型写的策略拿出来诚实重测——全部失败

`scripts/retest_llm_strategy_programs.py`：85 个去重后的策略程序，**原样**（我方不做参数搜索）跑 50 个币 × 5 个月 1h，前 60% 开发期 / 后 40% 留出期，扣除"持仓暴露 × 该币平均涨幅"只看择时能力。

| | |
|---|---|
| 每个策略中位交易数 | **3461**（原循环：4） |
| 开发期择时超额为正 | **2%** |
| 留出期为正 | 27% |
| 留出期 t>2 | **0**（Bonferroni 门槛 3.24 下也是 0） |

开发期和留出期排名相关 0.50，主要来自"换手高的两段都被手续费吃掉"，不是技能延续。

**结论**：大模型写的单品种技术指标策略，给足样本后没有一个有择时能力。这和 7 月三周期 1500+ 样本的规则研究结论一致。

## 5. 唯一符合全部条件的方向：Binance Alpha → 主站上币预测（已开始采集）

大模型要有优势，需要同时满足：信息以文本为主、关注度低、定价慢（周/月级）、结果可客观验证。前四个测试都不满足。这一个满足：

- Alpha 代币升到 Binance 主站是公认的价格催化剂；判断"哪个项目会被升级"需要读项目材料、生态、持币分布，是大模型的强项。
- 目录里 678 个代币，**118 个（17%）已升到主站**，其中 **90 个升级后从 Alpha 下架**。
  → 修正此前可行性研究的误读：`fully_delisted` 17% 大部分不是"死亡"，而是**毕业**。
- 问题：每周快照**没有记录 `listingCex`**，历史上无法知道谁在哪天升级。

**已做**：`scripts/snapshot_alpha_fundamentals.py` 从今天起记录 `listing_cex / cex_states / cex_coin_name / bn_exclusive`。8~12 周后就有"升级事件 + 升级前基本面"的面板。

**下一步设计（只记录、不交易）**：每周让大模型读每个在 Alpha 的代币资料，输出"30 天内升主站的概率"，落盘；到期用 Brier 分数对比两个基准——历史频率、以及只用数值基本面（持币、流动性、成交）的简单模型。**大模型只有同时赢两个基准才算有用。**

## 让大模型交易"成功"的路线图

总原则：大模型负责**读和写**（文本→特征、想法→代码），统计检验负责**判**，前向数据负责**终审**。

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| 1 | 研究循环 v2：把搜索空间从 BTC/ETH 1h 技术指标改到**周度横截面（~110 个山寨）+ 事件日历**；多币合并评估，≥300 笔或 ≥30 个独立事件才进门禁；每个被测过的公式记入试验台账，门槛随总试验数上调 | 系统里唯一通过验证的就在这个空间；样本量问题一次解决 |
| 2 | 研究循环只给大模型**匿名化**的特征（不给币名和日期），它只能提公式、看不到答案 | 大模型训练数据覆盖 2025~2026，直接给币名会"背出"谁拉过盘（前视偏差） |
| 3 | Alpha 上币概率：前向记录 8~12 周再评估 | 唯一同时满足四个条件的方向 |
| 4 | 修数据源：`okx` 新闻源存的是网页语言菜单（2199 条 "English"/"Italiano"），`Binance` 源大多是无关网页，真正的上币公告只有 4 条 | 事件驱动研究的原料；不修什么都测不了 |
| 5 | 盘中自治代理保持纸面观察；不再在择时方向投入 | 五组独立检验全部证伪 |
