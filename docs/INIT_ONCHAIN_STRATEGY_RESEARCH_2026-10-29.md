# INIT 案例：韩国警示做空加入链上过滤的可行性

研究日期：2026-10-29，北京时间。结论：值得建立独立的“警示事件＋链状态／充提安全过滤”候选，优先验证是否减少尾部亏损。目前没有足够的历史链上收件，不能宣称新策略有效、已经避开 INIT 或可以实盘。现有账本和交易规则保持原样，原型未接入运行器。

## 本次查到的关键事实

1. **原事件包含资金通道中断。** Upbit 6708号 API 公告的发布时间为10月26日14:00 KST（北京时间13:00）；正文载明 INIT 于10月24日00:57 KST（北京时间10月23日23:57）起充提双停。其原文理由是安全事故。这里采用当前读取的官方公告；首次收件档案只保留了公告元数据，不能把这次读取的完整正文冒充当时冻结的文本版本。
2. **主链节点明显陈旧。** 本次查询 Initia 官方 RPC 和 REST，两者均返回主网 `interwoven-1` 的高度23,365,925，区块时间为10月23日15:41:30 UTC（北京时间23:41:30）。两条接口属于同一运营方，不算两家独立节点；另一个运营方返回503，所以不能将其失败当成全球停链的独立证明。安全策略可据“无法获得新鲜链状态”暂缓入场，无须把接口故障解释为链上卖压为零。
3. **普通负资金费预警没有在该时点触发。** 以币安历史数据重建，在原入场前最后一次已公布资金费率为 **+0.005%/次**，OI数量近6小时变化 **−0.73%**。在5分钟路径首次触及止损所在K线之前，最后一次费率为 **+0.000584%/次**，OI数量近6小时 **+4.26%**。因此“极端负费率＋OI暴增”不能被写成这次入场前的有效预警。OI采用合约数量，不用随币价上涨而机械增加的美元名义金额替代。
4. **现有持仓数据不够回测。** 韩国合并账本有6个前向标的事件、其中4个已结算；按入场前最近快照匹配，仅FET有一条BSC特定合约记录。BLUR、MANTRA、ZIL、EGLD、INIT均无对应记录。FET该记录也不代表全网原生持仓或交易所流向；相同日期／共同事件不能当独立样本。INIT在10月19日与26日的快照中明确列为缺失。
5. **原生供应和历史状态仍未核验。** 本次原生供应及历史区块查询未成功，未将失败写成零供应、零交易或零净流入。尚无经过历史标签校验的交易所原生INIT地址集合，也没有能复原原入场时刻的净流入数据。

链上事实与价格上涨之间，目前只能提出流动性隔离／空头风险的机制假设，不能把相关性写成已经证明的逼空原因。CEX内的撮合、库存和借币行为也无法全部从链上观察。

## 建议的独立候选

| 候选 | 规则 | 当前成熟度 |
|---|---|---|
| **A：警示做空安全过滤** | 保留原警示策略的入场时点和退出规则；及时确认充提双停则否决新空单；主链状态陈旧、身份不符、资料缺失则暂缓。单纯“暂停充值”不一概否决，因为它常随警示例行发生。 | 已实现离线原型，优先前向验证 |
| B：A＋原生币流入确认 | 只有事先确认标签、完整时间窗、完成实体去重的指定交易所原生币净流入为正，才交给原策略审核。包裹币、过期数据和事后地址标签均不确认。 | 原型可处理该输入，但缺真实合格流向数据 |
| C：复链后的反弹观察 | 等待出块和充提恢复并持续稳定，再独立研究反弹；安全事故或停链本身不构成做多信号。 | 仅假设，未实现交易规则、未回测 |

A是入场过滤层，不是独立价格预测，也不创造成交。即使放行，仍须经过原策略和风险审核。既有资金费／总亏损预算影子可以作独立对照；预算触发值不是最大损失保证，不用修改旧策略来美化结果。

## 时间边界与验证方案

- 每条特征必须有链／资产身份、来源、源事件时间、真实可用时间及实时／重建属性；源事件发生得早，不代表系统当时已经收到了它。
- RPC新鲜度与特征有效期暂用10分钟作为研究起点，不根据INIT盈利与否调参。网络性能不同，应在新前向登记前检查适用性。
- 用今天的节点回执重放10月27日入场，原型返回“数据在决策时不可用、暂缓”，不会生成伪造的历史成交或“避免了43%损失”的收益。
- 未来另立带时间戳的前向研究，固定A/B与原版同一候选事件、同一原定入场机会；记录放行、拒绝、未知、漏掉的盈利事件和延迟。至少20个事件簇时初步复核尾部亏损、均值、覆盖率及机会成本；这个数量不是显著性证明或实盘放行标准。
- 单独做排除INIT后的敏感性检查。把INIT直接删掉得到的原版均值回升，只是事后敏感性分析，不能算A/B的回测收益。当前新策略绩效保持为空。
