# AI 研究页改为研究进展台 · 2026-11-07

取代 [9/8 的重设计方案](AI_RESEARCH_PAGE_REDESIGN_PLAN_2026-09-08.md)。那份方案想把“提案 → 回测 → 注册”这条线理顺，只做了一部分。

## 为什么换方向

改造前核对的数据：

- 88 个提案有 86 个被拒，174 个候选没有一个通过验证，最后一条记录是 9/26。
- 实际在跑的研究是纸面账本（接口 29 本）和因子循环 v3，但它们压在页面最底部的折叠抽屉里。
- 页面首屏的主按钮启动的是已暂停的 v1 循环。

所以这一页的问题不是排版，而是主线已经换了。页面现在先回答三件事：今天有没有要决定的事、账本走到哪了、因子循环在做什么。

## 页面结构

| 位置 | 内容 | 什么时候加载 |
|---|---|---|
| 状态条 | 待决定、需要看一眼、账本数、v3 状态 | 进入页面 |
| 账本总表 | 全部账本，按离判定远近排序 | 进入页面，两分钟内不重复请求 |
| 研究循环 v3 | 状态和冻结因子，台账折叠 | 进入页面 |
| 其他研究循环 | v1、v2 | 状态随页面刷新 |
| 逐笔记录 | 旧的 15 个账本面板 | 展开时 |
| 策略提案档案 | 提案、候选、数据诊断 | 展开时 |

下单前 AI 复核移到策略页，主流币聚合信号移到 AI 自治代理页。策略页的账本表改成入口按钮。

切到这一页的 API 请求从 24 个降到 5 个，页面高度从约 9500 px 降到约 1470 px（1440 宽，抽屉全关，各测一次）。

## 判定规则

- **需要决定：** 账本结论是退役或确认、样本已满，或因子前向已确认，或提案候选通过验证后无人处理。
- **需要看一眼：** 账本状态为异常或延迟，或 v3 最近失败。
- **`late` 不算异常。** 它表示事件发现太晚，按协议记录但不计入。
- **预计到判定只是估算。** 按目前样本速度线性外推到 `min_n`，不含部分账本“满 N 个月也判”的时间条件。

## 同时修掉的行为

- 被拒候选不能再注册。之前手动目标会把拒绝结论改写成纸盘（`promote_existing_candidate`）。备选候选（边缘或与运行中策略重复）按原设计仍可人工决定。
- 一键研究只跑到候选结果，不再自动调用部署接口。接口本身保留。
- `forward_observing` 候选显示“观察中”。它的 `decision` 是 `reject`，但这不是最终结论，通过观察后循环会改成 `paper`。
- 主流币信号每次刷新都报 `selectedSymbol is not defined`，已修。
