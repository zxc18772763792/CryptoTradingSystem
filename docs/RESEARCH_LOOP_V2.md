# 研究循环 v2：大模型提出周度横截面特征（2026-09-26）

## 为什么重写

v1（`core/ai/research_loop_service.py`）让大模型写 BTC/ETH 1h 技术指标策略，用 30 天回测选优。
第二轮研究（`docs/LLM_TRADING_RESEARCH_ROUND2_2026-09-25.md`）证明它结构上找不到东西：每个候选中位 4 笔交易，
85 个程序在 50 币 × 5 月重测后留出期无一显著。

v2 把大模型放到唯一验证过有优势的问题上——**每周一给 ~110 个山寨币排序，前 20% 在 30 天内翻倍的概率是否更高**——
并把"大模型负责提想法、统计负责判断、前向数据负责终审"写进代码。

## 流程

```
LLM（只见匿名面板事实 + 自己的开发期结果）
  → JSON 公式（封闭 DSL，不执行代码）
  → 开发期 / 留出期横截面评估（留出期对 LLM 隐藏）
  → 闸门（多重检验门槛随试验台账增长）
  → 冻结 → 只用冻结后的新周度数据终审 → 人工决定是否并入周度模型
```

研究专用：不注册策略、不下单、不改配置。默认**关闭**，在 AI 研究页"研究循环 v2"卡片启用或手动跑一轮。

| 文件 | 作用 |
|---|---|
| `core/research/xs_feature_dsl.py` | 公式 DSL：5 个基础列、二元/一元/窗口算子，窗口 ≤180 天、深度 ≤5、节点 ≤20 |
| `core/research/xs_panel.py` | 日频面板、30 天前向标签、周度归档拼接（后到的快照覆盖，市值只信快照当天） |
| `core/research/xs_evaluation.py` | 横截面评分（见下） |

| `scripts/generate_pump_watchlist.py` | 每周一额外写 `data/research/xs_panel/weekly_archive/<日期>.parquet`（前向证据） |
| API | `GET/PATCH /api/ai/research-loop-v2`，`POST /api/ai/research-loop-v2/run` |

## 评分与闸门

协议沿用已验证的周度模型：周一截面、市值 2e6 ~ 1.5e9、标签 = 未来 30 天最高收盘 ≥ 2 倍、开发期 ≤ 2026-02-15。

| 指标 | 含义 | 防的是什么 |
|---|---|---|
| lift | 特征前 20% 的翻倍率 / 全体翻倍率，**每 4 周取一个截面**、4 个相位平均 | 30 天标签跨 4 行周数据导致的伪重复 |
| z | 相对**按币整体打乱**的零分布 | 币级持续性（惯犯币）造成的假显著 |
| lift_ex_top3_coins | 去掉贡献最多的 3 个币后的 lift | 结论被一两个妖币撑起 |
| shortlist_lift / z | 在现有模型前 40% 内，按模型分 4 档、**档内**再按特征排，前一半的翻倍率提升 | 重新发现现有模型已有的信息 |

闸门（全部满足才冻结）：两期覆盖率 ≥ 60%；开发期 z ≥ 1.645；留出期 z ≥ 1.645；
**留出期 shortlist_z ≥ Bonferroni(台账大小)**；留出期 shortlist_lift ≥ 1.2；留出期 lift_ex_top3 ≥ 1.3。

前向终审（冻结后 ≥ 8 个成熟周）：shortlist_z ≥ 1.645、shortlist_lift ≥ 1.2、lift ≥ 1.3。

前向终审按**抓取时点**取数（2026-09-29 起，`xs_panel.load_archive_vintages` + `xs_evaluation.evaluate_formula_forward`）：
每份周归档只在自己的最后一个收盘日上出一个截面，特征和现有模型分都只用这份归档当时抓到的历史；
只有抓取时间晚于冻结时间的归档才计入。标签（其后 30 天收盘价）来自后续归档，收盘价是结果、不是特征。
不再用"后到覆盖先到"的拼接面板算特征——后一周的归档会重述约一年历史（OI 回退源、资金费率补齐等），
拼接后信号日的特征值可能是当时看不到的。归档抓取日无法证明（文件名非日期、`captured_at` 与文件名不符、
最后一根日线不是抓取前一天、文件损坏）时**整份拒收**，原因写进 `forward_archives_rejected`。
新归档（schema 2）逐行记录 `captured_at`、`oi_source`、`mcap_source`、`schema_version`；旧归档以文件名当日零点为抓取时间（偏保守）。

## 校准记录（改评分前必读）

这些都是在真实面板上实测后才定下的，不是拍脑袋：

1. **周内打乱的零分布不可用**：60 个随机的持续性特征里 25% 被判 z > 1.645（应为 5%）。
   原因：特征和翻倍都有币级持续性。改为"每个币整体换成另一个币的特征轨迹"后：p < 0.05 的比例 5%，z 标准差 0.96。
2. **等权混合检验不可用**：把特征与模型分 50/50 混合看前 20% 是否变好——所有候选都掉 0.4 ~ 0.9，
   因为现有模型很强（lift ~2.6），任何更弱的特征混进去都会稀释。它惩罚的是"弱"，不是"没有新信息"。
3. **不分档的短名单检验不够**：模型分的一份拷贝在短名单内仍有 1.27 的 lift（模型自身在前 40% 内的梯度）。
   按模型分分 4 档、档内排序后：拷贝降到 z = 0.66（不显著），随机特征误报率 2%。
4. **波动率会被反复"重新发现"**：成交量趋势、OI 与价格背离、收益加速度等单独 z 可达 3 ~ 4.7，
   短名单增量却 ≈ 1.0。这正是 v1 式评估会误判为"发现"的东西。

## 已知局限

- 留出期（2026-02 ~ 06）此前已被人工研究用来验证周度模型，不是完全"干净"；因此前向终审才是最终裁决。
- 前向数据从 2026-09-28 起才开始归档；冻结公式最早约 2026-12 能完成 8 周成熟标签。
- 大模型训练数据覆盖 2025 ~ 2026；匿名化只能挡住"按币名回忆"，挡不住公式选择上的间接泄漏——同样靠前向终审兜底。
- 本环境的 BLAS 会原生崩溃（0xc06d007f），评估代码只用逐元素运算；`Series.corr(method="spearman")` 也会崩，用 `xs_evaluation.spearman`。
