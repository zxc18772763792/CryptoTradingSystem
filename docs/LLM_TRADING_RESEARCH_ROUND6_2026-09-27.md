# 大模型交易研究 第六轮：用大模型读文档，扩大供给因子覆盖面（2026-09-27）

## 为什么做

前五轮的结论：大模型直接预测涨跌没有优势；有效的是供给侧结构事件，其中包括供给通胀因子（做多低增发、做空高增发）。
这个因子的瓶颈是覆盖面：DefiLlama 有解锁排期、又能在币安现货交易的代币只有 147 个，每月能排序的约 93 个。

币安 484 个 USDT 现货币种里，有 337 个没有排期。其中 187 个是 2024 年以后上市的，但不少是股票代币、迷因币和稳定币，真正有归属条款的大约 80–100 个（估计值）。

所以要问：大模型能不能读项目自己的文档，重建排期？

## 第 1 步：准确性检验（本轮）

**方法：**
- **测试集：** DefiLlama 已覆盖的币。每个币的排期适配器里，写着 DefiLlama 分析师当初参考的文档链接。上游仓库已不公开，改用一个 2026-04 的分叉。
- **流程：** 抓取这些文档的 HTML 正文（从不下载 PDF），交给研究模型（`generate_json`），输出结构化归属条款：各分配份额、TGE 解锁比例、悬崖期、线性期、频率。再由代码生成累计解锁曲线。
- **对照：** 在每个月初，用两条曲线分别计算未来 90 天供给增长（因子实际使用的量），再比较截面排序。
- **记忆基线：** 同一个模型不给文档、只凭记忆回答，用来衡量它是否只是记住了答案（训练数据污染）。

**脚本：**
- `scripts/vesting_llm_fetch.py`：抓取文档，得到 56 个币。
- `scripts/vesting_llm_extract.py`：抽取条款。
- `scripts/vesting_llm_compare.py`：与 DefiLlama 对照。

**结果：**

| 条件 | 可用排期 | 每月截面秩相关（中位数） | 分到同一三分位 | 多空腿被颠倒 |
|---|---|---|---|---|
| 读文档，历史月份（45 个月，每月约 14 个币） | 30/56 | 0.66 | 70%（随机为 33%） | 5.8% |
| 读文档，未来月份（2026-10 起，9 个月） | 同上 | 0.82 | 81% | 2.3% |
| 只凭记忆，历史月份 | 19/56 | 0.66 | 59% | 5.0% |
| 两种条件都能用的 12 个币：读文档 | | 0.86 | 77% | |
| 两种条件都能用的 12 个币：只凭记忆 | | 0.76 | 76% | |

每个币、每个月的 90 天增长绝对误差，中位数为 1.8 个百分点；参照值本身的中位数是 4.3%。

**解读：**
- **能用时，基本能用。** 抽取成功时，大模型给出的排序与 DefiLlama 高度一致，多空腿被颠倒的情况少于 6%。未来月份的一致性更高，因为那时大多只剩下平稳的线性释放。
- **失败时，它会如实说"不知道"，而不是编造。** 26 个失败的币里，大多数原因是：
  - 抓到的页面不对，或只有导航栏（文档站靠 JS 渲染）；
  - 页面只讲质押或回购，不讲归属；
  - 币本身是挖矿或通胀发行（LTC、CRV、TAO、SOL），没有归属表。

  失败时模型自己报出的置信度大多在 0.3 或以下。
- **记忆污染是真实存在的。** 对知名币，不给文档也差不多准。所以本次检验高估了它对冷门币的准确度：冷门币必须有文档才行。
- **误差最大的币：** COW、BERA、JTO、PYTH、ENA。原因是大额分配的起始日期或悬崖期理解有误。可以用"低置信度不纳入"来过滤。

## 下一步（未做）

1. **文档发现：** 未覆盖的币没有现成的文档链接。需要从 CoinGecko 的官网链接出发，找到代币经济页面，再衡量这一步的成功率。
2. **回测：** 用"DefiLlama 排期 + 大模型补充的排期"扩大后的币池，重跑供给因子回测，看效应是否保持、置信区间是否变窄。

注意：文档可能被事后修订，存在轻微前视偏差，结论里需要标注。

## 第 2 步：文档发现 + 扩池回测（2026-09-28）——瓶颈在"找文档"，不在模型

脚本：`scripts/vesting_llm_discover.py`（发现）、`scripts/vesting_llm_extract.py discovered.json discovered_extractions.json docs`（抽取）、`scripts/vesting_llm_factor_backtest.py`（回测）；排期曲线的构建挪到了 `core/research/vesting_spec.py`（附测试）。

**发现漏斗（337 个无排期的币安币种）：**

| 环节 | 数量 |
|---|---|
| 股票代币、稳定币、包装币等（按 CoinGecko 分类或名称排除） | 83 |
| CoinGecko 对不上 | 13 |
| 官网或文档里找不到候选页面（JS 渲染、反爬、没链接） | 157 |
| 找到候选页面 | 143 |
| 其中页面至少提到 vesting、cliff 或 unlock | 76 |
| **最终可用的排期**（置信度 ≥ 0.5、有排期的份额 ≥ 30%） | **12**（不设门槛为 16） |

- **自动发现只能多覆盖约 12–16 个币**，不是预想的 80–100 个。主要损失在找不到页面，以及页面里根本没有归属表；模型本身不是瓶颈。
- **已覆盖币的对照抽样也失败了。** 60 个已覆盖币里只找到 1 个的页面：大项目官网大多是 JS 渲染或有反爬（例如 ARB 返回 403）。所以"自动发现 + 抽取"的端到端准确度无法对照 DefiLlama 打分。
- **工程教训：** 代理在高并发下会丢连接。一开始把这类临时失败当成"页面不存在"缓存下来，导致已覆盖币几乎全部失败。现在只缓存真正的 4xx 或非 HTML 响应，并给每个币设了 5 分钟上限。

**扩池回测**（价格来自无幸存者偏差的币安现货面板，每组各自按三分位排序）：

| 组 | 月数 × 每月币数 | 多低空高（每月，扣成本） | 秩相关为负的月份 |
|---|---|---|---|
| DefiLlama 排期（147 个币，第五轮只有约 45 个） | 44 × 84 | +2.1%，90% 区间 [−0.4, +4.3] | **35/44（p = 0.0001）** |
| 仅大模型排期的新币（12 个） | 14 × 11 | +4.9%，区间 [−2.7, +14.2] | 9/14（p = 0.21） |
| 合并 | 44 × 87 | +2.0% | 35/44 |

- **新币方向一致，但样本太小，统计上不显著。** 它既不能证明、也不能否定大模型排期可用。
- **重要副产品：因子在大面板上变弱了。** 币池从约 45 个扩到 147 个后，秩相关方向仍然极其稳定（35/44 个月），但三分位多空收益降到 +2.1%/月，区间跨 0；2023–24 年约为 0，收益集中在 2025–26 年（+4.6%/月）。
- **跟踪器的规则不改。** 供给因子跟踪器登记的退役规则按回测均值 2.6% 计算"衰减线"。这条规则是预先登记的，不因事后看到的数据而修改；这里只把情况记录下来。

**结论：** 不把大模型排期接入供给因子跟踪器。增加的覆盖太少，也无法端到端验证。需要人工的地方：若日后有可用的代币解锁数据源（付费 API 或更好的搜索入口），可以复用 `vesting_spec` 和抽取脚本。
