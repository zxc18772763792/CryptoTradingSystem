# 韩国事件跟踪器请求与健康状态修复（2026-10-27）

韩国警示与上币跟踪器此前可能因一次合约或公告请求超时而中断整个更新，已有纸面持仓也随之延迟。Bithumb 的部分接口失败则会被当作空结果处理，页面无法区分缺信号和采集故障。异常信息为空的超时日志也未显示异常类型。

部署实测进一步复现 Upbit 的 `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`。系统/Conda 信任库之外补入已安装的 certifi 标准 CA 库后，同一公告请求返回200。共享 TLS 上下文现在合并两者并保持缓存；保留系统已有根证书、强制证书校验及域名校验，不关闭 TLS 验证。

## 修复范围

- 每轮对连接错误、超时及 HTTP 408/500/502/503/504 最多重试一次，间隔 250 毫秒；403/429 不立即重发。仍失败的调度任务约五分钟后再检查，成功后恢复原有周期。
- 公告/合约发现与已有持仓的行情、资金费更新分开。接口失败不据此把已有标的标为无永续，也不把资金费缺失记为零。
- 合并策略缺少任何公告输入时，暂停该轮新增事件认领，保留原警示标志基线以便恢复时继续发现；不以残缺输入判断哪家交易所先警示。
- 增加每轮尝试、最近完整成功时间、失败环节和重试次数。页面区分正常、采集/估值延迟及更新过期（75分钟），并显示失败原因。主统计与可选证据、影子实验的失败分别记录。
- 韩国跟踪器自身文件读写移到线程，仍在同一个串行研究 pass 内等待完成。未新增第二个账本写入进程。
- 策略页在 WebSocket 在线时通过每分钟的次级刷新读取研究跟踪器快照，避免长期停留在旧表格。
