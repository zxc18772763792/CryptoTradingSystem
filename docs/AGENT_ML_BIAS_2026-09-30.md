# 代理"99% 买入"的根因与修复（2026-09-30）

## 结论

1. 代理的规则聚合信号被 ML 组件主导，而这个 ML 模型对所有山寨币恒为 LONG。
   它是 BTC/USDT 1h 模型，17 个特征里 13 个是价格或成交量的绝对水平，训练时自己的质量闸门就没通过。
2. 修复分两步：
   - 加载器现在拒绝未通过闸门、特征版本过期、周期不符或币种越界的模型。
   - 特征集升级为 v2（全部无量纲）。
3. 按 v2 跨 53 个币重新训练后，模型不再偏向一侧，但信息量只有成本的约四分之一，闸门正确拒收。
4. **ML 组件目前不参与投票**：权重为 0，聚合信号只剩大模型情绪和规则因子。
5. 大模型"放行还是不做"的过滤价值：+0.16%/4h，90% 区间 [−0.27%, +0.67%]，不显著。
   做空方向实际从未被检验（16 次）。修复后需要重新积累数据再测。

## 一、为什么 99% 是买入（18,791 条决策日志，3/14–9/30）

| 组成部分 | 看多 | 看空 |
|---|---:|---:|
| ML | 14,728 | 155 |
| 规则因子 | 14,907 | 3,847 |
| 大模型情绪（约 55% 的时间不可用） | 6,627 | 1,688 |
| 聚合结果 | 88.5% | 9.9% |

代理的调用流程：
- 空仓时，只有聚合信号已经有方向、且过了置信度才调用大模型，否则直接持有。
- 模型只在"跟"与"不做"之间选，从不反向：
  - 看多提示：放行 1,224 次，持有 6,187 次（约 17% 放行）。
  - 看空提示：放行 16 次，持有 503 次（约 3% 放行）。
- 自动选币也偏好正在上涨的币：决策时 72% 的币 24 小时为正。

四者叠加，就是 1,224 买对 16 卖。

旧文档说"与规则一致率 100% = 模型复述输入"，这个解读不准确：一致是流程决定的。

## 二、ML 组件的实证（最近 60 天，15m）

生产文件 `models/ml_signal_xgb.json` 对应训练记录 `mlsig_btc_usdt_1h_20260413T120518304880Z_6992c71b`：
- 只用 BTC/USDT 1h 训练，时间 2025-12-14 → 2026-04-13。
- 质量闸门未通过：正类 F1 0.36，召回 0.29。
- 旁边的 sidecar manifest 是事后补写的桩文件（"restored sidecar"），里面没有闸门记录。

| 币 | 看多占比 | 价格等比放大到 BTC 水平后 | 看多时后 4 根上涨率 |
|---|---|---|---|
| ETH/SOL/BNB/DOGE/ADA/AVAX/LINK/ICP/ARB | 全部 100%，P(up)≈0.88 | 变成 90–99% 看空 | 等于该币基准率 |
| BTC | 19%（74% 看空） | — | 52.2%，基准 50.8% |

同一段走势，只是价格数字变了，信号就翻转。这说明模型用的是价格水平，而不是形态。

## 三、修复

**加载器**（`core/ai/ml_signal.py`）
- manifest 必须记录闸门已通过，特征版本必须是当前版本，否则拒绝加载。
- 推理时，K 线周期与训练周期不符就返回 FLAT。周期从特征索引推断。
- 单币模型用在其他币上也返回 FLAT。
- 聚合器把这种拒绝当作"不投票"，而不是"投 FLAT 票"，所以不会稀释其他组件（`core/ai/signal_aggregator.py`）。
- 回测和研究里直接加载 booster 的地方改用 `model_usability()` 先检查（`web/api/backtest.py`、`core/research/strategy_research.py`）。
  原先缺失的特征会被静默填 0。

**特征 v2**（`core/ml/pipeline.py`）
- 新特征：RSI、MACD/价格、均线偏离、布林带位置与宽度、ATR/价格、量比、动量、1 根与 4 根收益、实体比例、振幅比例。
- 测试确认：价格放大 3 万倍，特征完全不变。

**多币训练**（`scripts/train_ml_signal.py --symbols auto --timeframe 15m`）
- 按 K 线时间切分训练集和测试集，并留出 4 根 K 线（标签长度）的间隔。
- 标签不跨币。
- 闸门新增一条：整体或任一币单边预测超过 90% 即拒收。
- 只有通过闸门的模型才会覆盖 `models/ml_signal_xgb.json`。

## 四、重训结果（未通过，未发布）

`mlsig_pooled_15m_20260930T152559699343Z_c3769c45`：
- 数据：53 币，4/3 → 9/30；测试期从 8/25 开始，共 175,084 行。
- AUC 0.537；看多占比 15%，看空 8%；单币最大单边占比 50%。
- 闸门未过的原因：正类 F1 0.26，召回 0.17。

经济检验（测试期、1 小时、扣掉同一根 K 线的全币均值）：

| 口径 | 1 小时收益 |
|---|---|
| 最高分十分位减最低分十分位 | +0.046%，[+0.022%, +0.070%] |
| 阈值 0.6 看多（原始） | +0.154% |
| 阈值 0.6 看多（扣市场） | +0.012% |
| 山寨来回成本 | 约 0.15–0.20% |

信息量真实存在，但只有成本的约四分之一，原始收益基本是市场 beta。不发布是对的。

## 五、大模型过滤价值（`scripts/agent_filter_value.py`）

口径：
- 取同类提示：规则看多、空仓、确实调用了模型。
- 按模型的反应分组。
- 按"跟随聚合方向"计算相对同币随机时点的超额收益，同币 4 小时内去重，按日自助抽样。

| 分组 | n | 4h 超额 |
|---|---:|---:|
| 放行 | 158 | −0.16% |
| 模型拦下 | 247 | −0.32% |
| 模型报错未判断（天然对照） | 142 | −0.45% |

放行减拦下的差：1h +0.08%，4h +0.16% [−0.27%, +0.67%]，24h +0.05%，均不显著。

ML 修复后，聚合信号已经变了。需要在 10 月之后的新数据上重跑：

```
python scripts/agent_filter_value.py --since 2026-10-01
```
