# Coinglass 数据目录（中转站 vip2.coinglass.site）

查阅用的常备文档：通过中转站能拿到哪些 Coinglass 数据、你的套餐能用哪些、山寨币有没有、历史有多长，以及我们用过、检验过什么。

- 最近核实：2026-10-11（逐个接口实测，方法见第七节）
- 实测原始结果：`data/premium/coinglass/catalog_probe.json`（本地文件，不入库）
- 接口来源：Coinglass 官方 v4 接口文档（docs.coinglass.com，约 160 个）、中转站使用手册（`F:\9_Crypto\docs\Coinglass_LSR_API_用户使用手册_v4.docx`）

## 一、账户与额度

- **地址：** `https://vip2.coinglass.site`，路径与 Coinglass 官方相同，但不带 `/v3`、`/v4` 前缀（`COINGLASS_STRIP_API_VERSION=true` 自动去掉）。
- **认证：** 请求头 `X-API-Key`。密钥在 `config/coinglass_api_key.txt`，不入库。
- **套餐：** Coinglass 标准版 + 中转站 LSR 专业版。两类额度分开计算，各 **11 次 / 滚动 60 秒**，和后台采集、存档任务共用。
- **查套餐和额度：** `GET /api/gateway/account`，不消耗业务额度，自身限 10 次/60 秒。10/11 查询：Coinglass 标准版、LSR 专业版，各 11 次/60 秒；WebSocket 和 MCP 都未开通；不返回到期日。
- **判断成功：**
  - Coinglass 接口看 `code == "0"`；
  - LSR 接口看 `success == true`；
  - HTTP 200 但 `code == 40300`，表示套餐不含这个接口。
- **限流：**
  - 中转站按滚动 60 秒计数，429 时按 `Retry-After` 等待；
  - 本地预算账本（`COINGLASS_RATE_LIMIT_PER_MIN=11`）按自然分钟计数，所以账本没满也可能 429；
  - 批量下载控制在每分钟约 5 次。
- **到期：** 账户接口不一定返回到期日，到期要靠你告知。10/8 到期后 401，10/9 续费恢复。

## 三、中转站自有的多空比产品（LSR 专业版）

只有实时值，没有历史。Coinglass 官方没有这组数据。

| 接口 | 内容 |
|---|---|
| `/api/lsr/signal/{symbol}?mode=trader\|whale` | 单币多空结构 |
| `/api/lsr/signals?symbols=...` | 批量查询（专业版） |
| `/api/lsr/ranking?mode=&sort=&order=&limit=50&offset=` | 约 740 个币的排行榜，每页 50（专业版） |
| `/api/lsr/status`、`/api/lsr/health` | 数据新鲜度 |
| `/api/lsr/funding-rate/arbitrage` | 跨交易所资金费率套利候选（专业版） |
| `/api/lsr/consensus/v1/...` | KOL 共识，只覆盖 BTC/ETH/SOL/DOGE/BNB（专业版） |

单币字段（`trader_` 前缀是同一组字段的别名）：

| 字段 | 含义 |
|---|---|
| `ratio`、`ratio_30m` | 聪明钱多头名义价值 / 空头名义价值（全周期口径、最近 30 分钟口径） |
| `delta_2m`、`delta_30m`、`delta_4h` | 比值与约 2 分钟、30 分钟、4 小时前之差 |
| `whale_ratio`、`whale_delta_*`、`whale_ratio_30m_ago` | 大户多头持仓数量 / 空头持仓数量，及其变化 |
| `long_notional`、`short_notional` | 聪明钱两侧名义价值（USDT） |
| `long_traders`、`short_traders`、`long_whales`、`short_whales` | 两侧人数 |
| `long_avg_entry`、`short_avg_entry`、`whale_long_avg_entry`、`whale_short_avg_entry` | 两侧平均入场价（可算他们当前的浮盈浮亏） |
| `whale_long_qty`、`whale_short_qty`、`whale_total_qty` | 大户两侧持仓数量 |
| `ov_*` | 持仓概览：多空比、持仓量、人数、平均入场价、当前盈利人数（`ov_long_profit_traders` 等） |
| `oi_mcap_ratio` | 持仓价值 / 市值 |
| `rank` | 按所选模式的多空比排名 |

口径来自币安的信号数据，不是所有交易所全部账户。比值大于 1 不代表上涨概率；比值很高也可能是空头分母很小。

## 四、实时推送（WebSocket）

- 需要单独开通。账户接口里的 `data.websocket.enabled` 表示是否开通。10/11 查询：未开通（开通后限 1 个连接、5 个频道）。
- 流程：
  1. `POST /api/gateway/ws-ticket` 换一次性票据（60 秒内有效）；
  2. 连接 `wss://vip2.coinglass.site/ws/coinglass`，5 秒内发认证帧；
  3. 订阅频道。
- 频道：
  - `liquidation_orders`：逐笔爆仓推送，跨交易所；
  - `futures_ticker@Binance_BTCUSDT` 这类合约行情。
- 推送不按 HTTP 请求计次，连接数和频道数以账户返回为准。

## 五、已知的坑

- **日线多空比是当天 00:00 的快照，不是收盘值。** 描述"第 D 天结束时"的是 D+1 那根。持仓量等开高低收数据的日线是正常的收盘值。
- **多空比字段只保留两位小数。** 需要精度时，用多头、空头占比相除。
- **一次请求的条数上限：** 4 小时、1 小时线一次最多 1000 根，要往回分页；给了 `start_time`、`end_time` 时，日线一次能返回 1000 多根。
- **coins-markets 每页最多 200 个币**，全部约 1500 个币要 8 页。
- **合计类接口（爆仓、主动买卖、CVD、挂单深度、U/币本位持仓、合约/现货成交比）必须带 `exchange_list`**，接口说明虽然写的是可选，不带就返回 400。
- **其他参数：** 挂单深度的 `range` 是价格上下的百分比（如 `1`）；期权持仓历史要带 `unit`；Hyperliquid 多空比一次最多 1000 条。
- **服务端报错：** 基差（`/api/futures/basis/history`）和 S2F 模型返回 500，10/11 两次实测都一样。
- **爆仓热力图：** 单交易所版本需要专业版；多交易所合计版本标准版就能用，山寨币也有。`range` 最长 `90d`（6 小时一格，`30d` 是 2 小时一格），总是截止到现在，不能指定起点；`180d`、`1y` 返回"time nonsupport"。一个币 30 天的响应约 600KB。成交足迹同样需要专业版。
- **中转站偶尔整体不可达：** 10/11 约 09:00–09:30（UTC）直连和走代理都超时，之后自行恢复。存档任务会在下一轮自动重试。
- **1000 倍合约在 Coinglass 里是另一个币。** 币安、Bybit 把 PEPE、BONK、FLOKI、LUNC、SHIB 做成 1000 倍合约（如 1000PEPE；Bybit 的 SHIB 叫 SHIB1000）。Coinglass 把它们和不带前缀的同名币分开统计，全币快照里也是分开的几行，SHIB 有 SHIB、1000SHIB、SHIB1000 三行。按 "PEPE" 查合计接口，只包含名字叫 PEPE 的合约：
  - 10/11 实测 24 小时爆仓（币安 + OKX + Bybit）："PEPE" 是 61,761 美元，正好等于 OKX 一家；三家的 1000PEPE 和 PEPE 合计 330,713 美元。
  - 全部交易所的持仓量（10/11 18:00 全币快照）：PEPE 3.0 亿、1000PEPE 1.4 亿；BONK 只有 0.05 亿，1000BONK 0.45 亿。
  - 要拿全量，就把几个名字分别查再相加；资金费率要按持仓量加权。
  - **对我们的影响：** 10/11 的单因子研究、组合研究、日线数据库和七日合成组合，对这 5 个币都只用了不带前缀的名字。结果是爆仓和主动买卖只有 OKX 一家，持仓量缺币安和 Bybit（BONK 只覆盖约 10%）。
  - 回测和跟踪器口径一致，冻结规则不改，131 个币里只有这 5 个受影响。多空比用的是币安交易对（1000PEPEUSDT），不受影响。

## 六、我们用过和检验过的

- **在用：**
  - 雷达和周度名单：全币快照、交易对持仓量、交易对资金费率；
  - 雷达拥挤度卡片：LSR 排行榜；

- **10/11 起存档：** 全币快照每天 4 份、131 个币的 7 天爆仓地图每天 1 份（`core/research/coinglass_snapshot_archive.py`）。
- **检验过：**
  - 10/9 多空比（用币安的同类数据）：没有信号，见 `docs/LSR_POSITIONING_STUDY_2026-10-09.md`；
  - 10/11 八个单信号（持仓量、资金费率、爆仓、散户/大户多空比、主动买卖）：单独都不够付成本，见 `docs/COINGLASS_POSITIONING_STUDY_2026-10-11.md`；
  - 10/11 多因子合成、组合形态、过滤：7 天合成组合有一点扣成本后的优势，见 `docs/COINGLASS_COMBINATION_STUDY_2026-10-11.md`。
- **还没检验、而且有山寨币历史的：** 净多空持仓、CVD、订单簿挂单深度（2024-10 起）、U 本位/币本位持仓、合约资金净流入、Hyperliquid 多空比（2025-07 起）。合计爆仓热力图只有最近 90 天，可以马上对这 90 天做初步检验，更长的需要定期存档。

## 七、怎么重新核实

```bash
python scripts/coinglass_catalog_probe.py                 # 逐个接口实测：约 200 次请求、每 15 秒一次，可断点续传
python scripts/coinglass_catalog_probe.py --retry-failed  # 只重测出错或返回为空的接口
python scripts/coinglass_catalog_probe.py --table         # 用已存结果重新生成第二节的表格
```
